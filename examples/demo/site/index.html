Checkout API outage: database failover critical
Resolved · started 2024-04-18 12:00:00 UTC · duration 2h 20m · 7 affected checks
  • 2024-04-18 12:00:00 UTC investigatingAutomated check "Checkout API" started reporting down.
  • 2024-04-18 14:20:00 UTC resolvedAutomated check "Checkout API" recovered to up.

Postmortem

Summary: Checkout requests began failing for all customers after our primary database's automatic failover picked a replica that had not fully caught up on replication.

Root cause: A misconfigured replication lag alert meant on-call was not paged when the replica fell behind. When the primary failed a routine health check, the orchestrator promoted the lagging replica, which briefly rejected writes with schema mismatches.

Remediation: We reconfigured the replication lag alert threshold from 60s to 10s, added a pre-promotion freshness check to the failover orchestrator, and added this exact scenario to our quarterly failover drill.
